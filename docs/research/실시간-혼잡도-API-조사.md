# 여백 실시간 혼잡도 API 조사 및 비교

> 조사 기준일: 2026-08-27  
> 조사 범위: 대한민국에서 앱이 실제 호출할 수 있고, 사람 또는 장소의 현재 혼잡도를 제공하는 공개 API

## 결론

여백의 첫 버전은 **서울시 실시간 인구데이터 API**를 주 데이터 소스로 사용하는 것이 가장 현실적이다.

- 무료이며 상업적 이용과 변경이 가능한 공공누리 제1유형 데이터다.
- `여유`, `보통`, `약간 붐빔`, `붐빔`의 4단계 혼잡도와 추정 인구 범위, 향후 12시간 예측값을 제공한다.
- 서울의 주요 121개 장소만 지원하고 한 번에 한 장소만 조회할 수 있다는 한계가 있다.
- API 응답에 지도 영역 좌표가 포함되지 않으므로, 데이터셋에서 제공하는 121개 장소 영역 파일을 받아 지도 폴리곤으로 변환해야 한다.

서울 밖으로 서비스 범위를 확장할 때는 **SK텔레콤 장소 혼잡도 API**를 검토한다. 지원 POI·상권의 혼잡도를 제공하지만, 무료 호출량이 매우 적고 실제 서비스 트래픽에는 비용이 발생한다.

지하철 데이터는 목적에 따라 분리해야 한다. 역별 승하차 인원은 과거 수요 패턴을 만드는 보조 데이터이고, 칸별 혼잡도는 열차 탑승 화면을 위한 데이터다. 둘 다 지역의 현재 보행 혼잡도를 직접 대체하지 않는다.

## 요청한 4개 API 반영 상태와 판정

| API | 기존 문서 상태 | 이번 분석 결론 | 여백에서의 역할 |
|---|---|---|---|
| TMAP/SKT 칸별 지하철 혼잡도 | 개요만 포함 | 통계성 칸 혼잡도와 실시간 상품을 구분해야 함 | 열차·칸 추천 보조 기능 |
| 서울교통공사 역별 승하차 인원 | 누락 | 시간대별 승하차 **흐름**이며 현재 재실 인원이 아님 | 역 수요 베이스라인·예상 혼잡도 |
| 서울 실시간 인구데이터 | 상세 포함 | MVP 지도 혼잡도 주 데이터로 유지 | 지도 폴리곤의 현재 혼잡도 |
| 서울 실시간 도시데이터 | 선택표에만 포함 | 인구 외 교통·날씨·행사가 필요할 때 상세 API로 사용 | 장소 상세 화면의 통합 컨텍스트 |

## 1. 서울시 실시간 인구데이터 API

### 제공 내용

[서울시 실시간 인구데이터 공식 페이지](https://data.seoul.go.kr/dataList/OA-21778/A/1/datasetView.do)는 서울 주요 121개 장소의 실시간 인구 현황을 제공한다. 원천 데이터는 통신 신호를 바탕으로 전체 인구를 추정한 값이다.

주요 응답 필드는 다음과 같다.

| 필드 | 의미 | 여백에서의 사용 |
|---|---|---|
| `AREA_NM` | 장소명 | 지도 라벨 |
| `AREA_CD` | 장소 코드 | 내부 장소 ID |
| `AREA_CONGEST_LVL` | 혼잡도 4단계 | 폴리곤 색상과 상태 문구 |
| `AREA_CONGEST_MSG` | 혼잡도 설명 | 상세 화면 안내 |
| `AREA_PPLTN_MIN` | 추정 인구 최소값 | 예상 인구 범위 |
| `AREA_PPLTN_MAX` | 추정 인구 최대값 | 예상 인구 범위 |
| `PPLTN_TIME` | 데이터 기준 시각 | 최신성 표시 |
| `FCST_PPLTN` | 예측 인구 배열 | 시간대별 혼잡도 차트 |

혼잡도는 최근 28일의 동일 장소 인구, 장소 면적 대비 밀집도, 장소 특성 등을 반영해 `여유`, `보통`, `약간 붐빔`, `붐빔`으로 산출된다. 자세한 산출 방식과 데이터 지연은 [서울 실시간 도시데이터 매뉴얼](https://data.seoul.go.kr/SeoulRtd/downloads/%EC%8B%A4%EC%8B%9C%EA%B0%84_%EB%8F%84%EC%8B%9C%EB%8D%B0%EC%9D%B4%ED%84%B0_%EB%A7%A4%EB%89%B4%EC%96%BC.pdf)에서 확인할 수 있다.

### 호출 예시

```http
GET http://openapi.seoul.go.kr:8088/{SEOUL_API_KEY}/json/citydata_ppltn/1/5/{AREA_NAME_OR_CODE}
```

예를 들어 장소 코드나 URL 인코딩한 `광화문·덕수궁`을 마지막 경로에 넣는다. 샘플 키는 광화문·덕수궁만 조회할 수 있으며, 전체 장소는 인증키가 필요하다.

### 갱신과 지연

- 실시간 인구 원천값은 5분 단위로 집계된다.
- 통신 데이터를 전체 인구로 확장·보정해 제공하기까지 약 15분이 걸린다.
- 앱에서는 `PPLTN_TIME`을 기준으로 최신성을 판단해야 하며, 단순히 요청 시각을 데이터 시각으로 표시하면 안 된다.
- 네트워크 호출 주기를 데이터 생성 주기보다 짧게 잡아도 새 데이터가 생기지 않으므로 5분 캐시를 기본값으로 권장한다.

### 장점

- 무료로 시작할 수 있다.
- 혼잡도와 추정 인구가 앱 기능에 바로 사용할 수 있는 형태로 제공된다.
- 향후 12시간 예측값이 있어 “지금보다 덜 붐비는 시간”을 추천할 수 있다.
- 데이터셋 페이지의 이용허락범위는 공공누리 제1유형으로, 출처 표시 조건에서 상업적 이용과 변경이 가능하다.

### 제약

- 서울 전역의 임의 좌표가 아니라 미리 정한 121개 장소만 제공한다.
- API 한 번에 한 장소만 호출할 수 있다. 지도 전체를 갱신하려면 백엔드에서 장소별로 호출하고 캐시해야 한다.
- API 응답 자체에는 장소 폴리곤이나 대표 좌표가 없다. 공식 데이터셋에 첨부된 `서울시 주요 121장소 영역` 파일을 별도로 내려받아 GeoJSON 등으로 변환해야 한다.
- 장기 과거 데이터는 이 API가 제공하지 않는다. 추세 분석이 필요하면 여백 서버가 이용조건을 확인한 뒤 자체 집계 데이터를 저장해야 한다.
- 공개 서비스 전 서울 열린데이터광장의 인증키 운영 조건과 호출 정책을 다시 확인해야 한다.

## 2. SK텔레콤 장소 혼잡도 API

### 제공 내용

[SK open API 장소 혼잡도](https://openapi.sk.com/products/detail?svcSeq=56)는 쇼핑·여가 장소와 상권의 혼잡도 및 방문자 통계를 제공한다.

- 지원 POI와 상권 목록
- 실시간·시간대별·통계성 장소 혼잡도
- 실시간·시간대별·통계성 상권 혼잡도
- 일자별 방문자 수, 유입력, 연령 분포, 방문자 유형
- 혼잡도 수치와 1~4 단계 레벨

실시간 장소 혼잡도는 요청 시점에서 가장 최근에 집계된 값이며, 조회 시점 기준 1시간 동안의 **1㎡당 추정 방문자 수**를 기반으로 한다.

### 주요 엔드포인트

```http
GET https://apis.openapi.sk.com/puzzle/place/meta/pois
GET https://apis.openapi.sk.com/puzzle/place/meta/areas
GET https://apis.openapi.sk.com/puzzle/place/congestion/rltm/pois/{poiId}
GET https://apis.openapi.sk.com/puzzle/place/congestion/rltm/areas/{areaId}

appKey: {SK_APP_KEY}
Content-Type: application/json
```

먼저 메타 API로 지원하는 `poiId` 또는 `areaId`를 확보한 뒤 해당 ID의 혼잡도를 조회하는 방식이다. 임의 위·경도를 보내 전국 모든 지점의 혼잡도를 받는 API는 아니다.

### 요금

[장소 혼잡도 요금 페이지](https://openapi.sk.com/products/calc?menuSeq=263&svcSeq=56)에 표시된 기준은 다음과 같다. 요금은 변경될 수 있으므로 계약 직전에 다시 확인해야 한다.

| 요금제 | 표시된 호출 조건 |
|---|---|
| Free | 월 10건 |
| Basic | 33원/건, 일 한도 100건 |
| 해커톤 | 11원/건, 월 한도 3,000건, 담당자 확인 필요 |
| 기업 | 사용량에 따라 별도 문의 |

TMAP 상품에 포함된 `puzzle 장소 혼잡도`는 [TMAP 요금 페이지](https://openapi.sk.com/products/calc?menuSeq=5&svcSeq=4)에서 별도 조건으로 제공된다. 현재 페이지에는 Free 3건/일, Premium 8.8원/건으로 표시되어 있다. 같은 데이터라도 가입한 상품에 따라 한도와 요금이 달라질 수 있으므로 프로젝트 생성 시 선택한 상품 기준으로 확인한다.

### 장점

- 서울시의 고정된 핫스팟 체계와 달리 SKT가 지원하는 POI와 상권을 다룰 수 있다.
- 장소와 상권 단위의 실시간 혼잡도를 같은 체계로 받을 수 있다.
- 방문자 통계까지 있어 이후 개인화나 장소 추천으로 확장하기 좋다.

### 제약

- 무료 한도는 실제 지도 서비스를 운영하기에 부족하다.
- 지원 대상은 SKT가 제공하는 POI·상권 목록으로 제한된다.
- 장소 목록 조회도 호출량에 포함될 수 있으므로 목록을 자주 다시 받지 말고 서버에 캐시해야 한다.
- 상용 출시 전 데이터 표시, 저장, 재가공, 제3자 제공에 관한 최신 상품 약관을 확인해야 한다.

## 3. TMAP/SKT 칸별 지하철 혼잡도 API

이 이름으로 접하게 되는 API는 **통계성 API**와 **실시간 상품 메뉴**를 구분해서 봐야 한다. 둘을 모두 “실시간 칸별 혼잡도”라고 부르면 구현 단계에서 데이터 의미를 잘못 해석할 수 있다.

### 3.1 TMAP 대중교통의 통계성 칸 혼잡도

[TMAP 대중교통 진입 역 기준 칸 혼잡도](https://transit.tmapmobility.com/docs/puzzle/car)는 특정 역으로 진입하는 열차의 칸별 혼잡도를 10분 간격으로 제공한다.

```http
GET https://apis.openapi.sk.com/transit/puzzle/subway/congestion/stat/car
    ?routeNm={노선명}
    &stationNm={역명}
    &dow={MON|TUE|WED|THU|FRI|SAT|SUN}
    &hh={05..23}

appkey: {SK_APP_KEY}
```

핵심 응답은 `congestionCar` 배열이다. 각 원소가 객차 한 칸의 혼잡도이며, 공식 문서는 **한 칸 승객 160명을 100%**로 환산한다고 설명한다. `statStartDate`와 `statEndDate`도 함께 오므로 현재 열차를 직접 센싱한 값이 아니라 통계 산출 기간을 가진 예상값임을 알 수 있다.

- 운행 시간대는 05:30~23:50이다.
- 시작역·종착역·이전역·상하행·일반/급행 조합별 값이 반환된다.
- 요일이나 시간을 생략하면 요청 시점과 같은 요일·시간대의 **통계값**을 반환한다.
- 운행하지 않는 열차 조합에는 혼잡도 `0`이 올 수 있으므로 `0 = 빈 객차`로 해석하면 안 된다.
- 역명과 노선명은 문서의 지원 목록에 맞춰 정확하게 입력해야 한다.

따라서 이 API는 “평소 이 시간에 어느 칸이 덜 붐비는가”를 추천하는 데 적합하다. UI에는 `실시간` 대신 `예상 칸 혼잡도` 또는 `평소 혼잡도`라고 표시하는 편이 정확하다.

### 3.2 SK open API의 실시간 열차·칸 혼잡도

[SK open API 지하철 혼잡도 상품](https://openapi.sk.com/products/detail?svcSeq=54)은 다음 기능을 별도 메뉴로 제공한다고 명시한다.

- 실시간 열차·칸 혼잡도
- 진입 역 기준 실시간 열차·칸 혼잡도
- 통계성 열차·칸 혼잡도
- 지하철역 출구 통행자 통계

상품 소개 기준 지원 범위는 수도권 1~9호선 및 신분당선이다. 다만 노선과 기능별 실제 지원 여부가 달라질 수 있으므로 앱에서 노선을 하드코딩하지 말고, 상품의 역 목록 API와 발급받은 앱 키로 응답 가능 범위를 먼저 검증해야 한다.

### 실시간 상품의 주의점

[현재 공개 요금 페이지](https://openapi.sk.com/products/calc?menuSeq=142&svcSeq=54)의 표에는 `지하철역 목록`, `통계성 열차 혼잡도`, `지하철역 출구 통계`의 Free·Basic·해커톤 조건만 표시되어 있다. **실시간 열차 혼잡도 그룹은 이 공개 요금 표에 명시되어 있지 않다.** 따라서 기존 문서처럼 월 10건 또는 33원/건을 실시간 칸 API 가격으로 단정하면 안 된다.

실시간 기능을 채택하기 전 다음을 SK open API에 확인해야 한다.

1. 신규 앱 키로 실시간 엔드포인트를 구독할 수 있는지
2. 지원 노선과 열차·칸 범위
3. 호출 한도와 운영 요금
4. 응답의 측정 시각, 지연 시간, 결측값 의미
5. 결과 저장·재가공·상업 서비스 표시 조건

### 여백 적용 판단

- 지도 메인 혼잡도: 사용하지 않음
- 지하철역 상세의 평소 혼잡 패턴: 통계성 API 사용 가능
- 현재 운행 열차의 덜 붐비는 칸 추천: 실시간 상품 계약과 실제 응답 검증 후 사용
- 실시간 값이 없을 때: 통계값으로 대체하되 반드시 `예상` 배지를 표시

## 4. 서울교통공사 역별 승하차 인원 API

[서울시 교통공사 지하철역 역별승하차인원 현황](https://data.seoul.go.kr/dataList/OA-22723/A/1/datasetView.do)의 서비스명은 `getStnPsgr`다. 통행일자와 시간대별로 역의 승차·하차 인원을 제공하며, 조회 가능한 기간은 최근 일주일이다.

### 호출 예시

```http
GET http://openapi.seoul.go.kr:8088/{SEOUL_API_KEY}/json/getStnPsgr/1/1000/{YYYYMMDD}
```

날짜 뒤에는 선택적으로 역 코드 또는 역명 검색 조건을 사용할 수 있다. 주요 응답 필드는 다음과 같다.

| 필드 | 의미 | 처리 방법 |
|---|---|---|
| `pasngDe` | 통행일자 | 기준 날짜 |
| `pasngHr` | 통행시간 | 시간대 버킷 |
| `lineNm` | 노선명 | 노선 필터 |
| `stnCd`, `stnNo`, `stnNm` | 역 식별 정보 | 역 메타데이터 연결 |
| `trnscdSeCd` | 선불·후불 등 카드 구분 | 합산 차원 |
| `trnscdUserSeCd` | 일반·청소년·우대 등 사용자 구분 | 합산 차원 |
| `rideNope` | 승차 인원 | 시간대 유입량 |
| `gffNope` | 하차 인원 | 시간대 유출량 |
| `crtrYmd` | 데이터 기준일 | 최신성 확인 |

### 데이터 의미

데이터셋 메타정보에는 갱신주기가 `실시간`으로 표시되어 있지만, 본문 설명은 **매일 갱신**이라고 명시하며 호출도 통행일자를 요구한다. 응답은 시간대별 교통카드 집계이므로 현재 순간의 플랫폼 인원이나 열차 혼잡도가 아니다.

또한 같은 역·시간에도 카드 구분과 사용자 구분별 행이 여러 개 반환된다. 여백에서 역별 수요를 계산할 때는 최소한 `통행일자 + 시간 + 노선 + 역` 기준으로 `rideNope`와 `gffNope`를 각각 합산해야 한다.

```text
stationHourlyBoardings = Σ rideNope
stationHourlyAlightings = Σ gffNope
```

`승차 + 하차`는 해당 역을 거친 이용량을 나타내는 지표로 사용할 수 있지만, 역 내부에 동시에 머무는 인원은 아니다. 승차에서 하차를 뺀 값 역시 환승·출입구·집계 경계를 반영하지 못하므로 재실 인원으로 표시하면 안 된다.

### 장점

- 무료이며 공공누리 제1유형으로 출처 표시 조건에서 상업적 이용과 변경이 가능하다.
- 시간대별 역 수요를 바탕으로 평소 붐비는 역과 시간을 학습할 수 있다.
- 실시간 데이터가 끊겼을 때 `평소 이 시간 혼잡 예상` 모델의 입력값으로 사용할 수 있다.

### 제약과 적용 판단

- 최근 일주일만 API로 조회되므로 장기 학습 데이터가 필요하면 허용 범위를 확인한 뒤 정기 적재해야 한다.
- 하루 데이터의 행 수가 크므로 1,000건씩 페이지를 순회한 뒤 서버에서 집계해야 한다.
- 메인 지도의 현재 혼잡도에는 사용하지 않는다.
- 지하철역 레이어의 수요 강도, 시간대별 차트, 예상 혼잡도의 보조 특성으로 사용한다.
- 더 넓은 운영기관을 일 단위로 비교하려면 별도의 [서울시 지하철호선별 역별 승하차 인원 정보](https://data.seoul.go.kr/dataList/OA-12914/A/1/datasetView.do)를 사용할 수 있지만, 이 데이터는 3일 전 값을 갱신하므로 현재 혼잡도용이 아니다.

## 5. 서울 실시간 도시데이터 API

[서울시 실시간 도시데이터](https://data.seoul.go.kr/dataList/OA-21285/A/1/datasetView.do)는 서울 주요 121개 장소의 여러 실시간 데이터를 한 응답에 묶어 제공한다.

### 제공 영역

- 실시간 인구와 혼잡도
- 실시간 상권 현황
- 도로 소통
- 주차장
- 지하철 도착·승하차 현황
- 버스 정류소 현황
- 사고·통제
- 따릉이
- 날씨·대기환경
- 전기차 충전소
- 문화행사
- 긴급재난문자·뉴스

### 호출 예시

```http
GET http://openapi.seoul.go.kr:8088/{SEOUL_API_KEY}/xml/citydata/1/5/{AREA_NAME_OR_CODE}
```

한국어 통합 API의 공식 명세는 반환 형식을 XML로 안내한다. 인구만 필요할 때 사용하는 `citydata_ppltn`과 달리 응답이 크고 여러 중첩 목록을 포함하므로 XML 파싱과 필드별 결측 처리가 필요하다.

### 실시간 인구데이터 API와의 차이

| 항목 | `citydata_ppltn` | `citydata` |
|---|---|---|
| 목적 | 인구·혼잡도만 조회 | 인구, 교통, 환경, 행사 등을 통합 조회 |
| 반환 형식 | JSON 또는 XML | 한국어 API 공식 명세 기준 XML |
| 응답 크기 | 작음 | 큼, 다수의 중첩 목록 포함 |
| 장소 범위 | 주요 121개 장소 | 동일한 주요 121개 장소 |
| 호출 단위 | 한 번에 한 장소 | 한 번에 한 장소 |
| 메인 지도 적합도 | 높음 | 낮음, 과도한 데이터 |
| 장소 상세 적합도 | 보통 | 높음 |

두 API의 인구 값은 같은 실시간 인구 체계를 사용한다. 따라서 메인 지도에서 `citydata`와 `citydata_ppltn`을 동시에 호출할 필요가 없다.

### 권장 사용법

1. 지도에 보이는 장소의 혼잡도는 `citydata_ppltn`으로 수집한다.
2. 사용자가 장소 상세를 열었을 때만 캐시된 `citydata`를 조회한다.
3. 인구, 교통, 날씨 등 하위 데이터마다 갱신 주기가 다르므로 각 필드의 기준 시각을 따로 표시한다.
4. 일부 장소에는 주차장·버스·행사 데이터가 없을 수 있으므로 빈 배열을 정상 상태로 처리한다.
5. 공식 공지에 따라 필드가 추가·삭제될 수 있으므로 엄격한 고정 스키마보다 하위 호환 가능한 파서를 사용한다.

이 API는 여백을 단순 혼잡도 지도를 넘어 “지금 가도 좋은가”를 판단하는 장소 상세 서비스로 확장할 때 가치가 있다. 예를 들어 혼잡도와 날씨, 진행 중인 행사, 주차 가능 면을 한 카드에 조합할 수 있다.

## 공개 API로 사용하기 어려운 후보

### Google Maps 인기 시간대

Google Maps 소비자 화면에는 장소별 인기 시간대가 보일 수 있지만, [Google Places API Place Details 공식 필드](https://developers.google.com/maps/documentation/places/web-service/place-details)에는 실시간 혼잡도나 Popular Times가 공개 응답 필드로 문서화되어 있지 않다. 비공식 스크래핑에 의존하면 안정성과 이용약관 문제가 생기므로 여백의 데이터 소스로 사용하지 않는다.

### 네이버 지도·카카오 로컬 API

[네이버 지도 API](https://www.ncloud.com/product/applicationService/maps)와 [카카오 로컬 API](https://developers.kakao.com/docs/latest/ko/local/dev-guide)는 지도 표시, 주소 변환, 장소 검색 등에 사용할 수 있지만 공식 공개 문서에서 장소의 실시간 인파 혼잡도를 제공하는 필드는 확인되지 않았다. 두 서비스는 **배경 지도 또는 장소 검색** 후보이지 혼잡도 원천 데이터 후보는 아니다.

### 서울 생활인구·일반 유동인구 통계

생활인구와 통신사 유동인구 통계는 구역별 인구 분석에는 유용하지만, 현재 시점의 혼잡도를 앱에 즉시 표시하는 용도와는 갱신 시점·제공 단위가 다르다. 실시간 API 장애 시 대체값으로 바로 사용하지 말고 `통계 기반 예상`이라고 명확히 구분해야 한다.

### 도로 교통 혼잡도

TMAP, 국가교통정보센터, 한국도로공사 등의 실시간 교통정보는 차량 속도와 도로 정체를 나타낸다. 보행 인파나 장소의 붐빔 정도와 의미가 다르므로 여백의 핵심 혼잡도와 섞지 않는다.

## 권장 MVP 데이터 구조

외부 API의 필드명을 앱 화면에서 직접 사용하지 말고, 백엔드에서 다음과 같이 정규화한다.

```json
{
  "placeId": "POI001",
  "name": "광화문·덕수궁",
  "level": "RELAXED",
  "levelLabel": "여유",
  "estimatedPopulation": {
    "min": 12000,
    "max": 14000
  },
  "observedAt": "2026-08-27T14:30:00+09:00",
  "fetchedAt": "2026-08-27T14:46:00+09:00",
  "source": "SEOUL_REALTIME_POPULATION",
  "isForecast": false
}
```

권장 내부 레벨은 `RELAXED`, `NORMAL`, `BUSY`, `CROWDED`, `UNKNOWN`이다. 데이터가 오래되거나 API가 실패했을 때 마지막 값을 현재 값처럼 보여주지 말고 `UNKNOWN` 또는 “업데이트 지연” 상태를 표시한다.

## 권장 구현 순서

1. 서울 열린데이터광장에서 인증키를 발급받는다.
2. 121개 장소 목록과 영역 파일을 내려받아 장소 코드와 지도 폴리곤을 연결한다.
3. 서버에서 장소별 API를 호출하고 최소 5분간 캐시한다.
4. API 키는 앱에 넣지 않고 서버 환경 변수나 비밀 저장소에서 관리한다.
5. `PPLTN_TIME`과 서버 수집 시각을 함께 저장해 데이터 지연을 감지한다.
6. 지도에는 폴리곤 또는 대표점으로 혼잡도를 표시하고 서울시 출처를 노출한다.
7. 장소 상세 화면이 필요할 때만 `citydata`를 호출하고 인구 API와 중복 호출하지 않는다.
8. 역별 수요 기능은 `getStnPsgr`를 별도 배치로 수집·합산하고 화면에 `통계 기반 예상`으로 표시한다.
9. 칸별 기능은 먼저 TMAP 통계 API로 프로토타입을 만들고, 실시간 상품의 이용 가능 여부와 요금을 확인한다.
10. MVP 사용성을 확인한 뒤 전국 확장이 필요할 때 SKT 지원 POI 목록과 월 예상 호출 비용을 산정한다.

## 최종 선택

| 단계 | 선택 | 이유 |
|---|---|---|
| MVP | 서울시 실시간 인구데이터 | 무료, 4단계 혼잡도와 예측 제공, 구현 가능성이 가장 높음 |
| 장소 상세 고도화 | 서울시 실시간 도시데이터 | 교통·날씨·행사까지 한 화면에 결합 가능 |
| 역별 예상 수요 | 서울교통공사 `getStnPsgr` | 시간대별 승하차 흐름을 예측 베이스라인으로 활용 |
| 예상 칸 추천 | TMAP 통계성 칸 혼잡도 | 공개 명세로 구현 가능하며 데이터 의미가 명확함 |
| 실시간 칸 추천 | SKT 실시간 열차·칸 혼잡도 | 계약·지원 범위·요금·응답 스키마 확인 후 채택 |
| 전국 확장 검증 | SKT 장소 혼잡도 | POI·상권 범위 확장 가능, 비용과 지원 장소 검증 필요 |

여백의 첫 출시 범위를 서울로 한정하고, **“서울 주요 장소의 지금 혼잡도와 덜 붐비는 시간”**에 집중하는 구성이 데이터 품질과 비용 측면에서 가장 안전하다.
